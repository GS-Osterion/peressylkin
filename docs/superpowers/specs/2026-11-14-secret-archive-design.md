# Засекретить и Сжечь дело — дизайн

## Зачем

Архив дел копится: реабилитированные, давно сосланные — всё в одной таблице. Пользователь хочет
1) **засекречивать** дела: убрать из общей таблицы так, чтобы без администратора их нельзя было ни
увидеть, ни изменить, но папку по-прежнему можно было реабилитировать (из окна администратора);
2) **сжигать** дела: стереть запись полностью, без следа и без акта об уничтожении.

## Цели

- «Засекретить» — в главном окне, для дела в статусе «сослан» или «реабилитирован». Работает без прав
  администратора. Первый раз — предупреждение: «Засекреченные дела выдаются к просмотру только по
  санкции прокурора» (с галочкой «больше не показывать» не нужно — показывается один раз, флаг в
  настройках).
- Засекреченное дело исчезает из общей таблицы, «Личного дела», `list`, `status`.
- Секретный архив закрыт правами Windows: читать и править — только процесс с правами администратора.
  Обычный процесс (программа без прав, ИИ-агент) может только дописать в него новое дело.
- У засекреченной сосланной папки снимается печать (иконка папки — по умолчанию).
- Кнопка «Секретные записи» в главном окне — только если окно запущено от администратора; без прав
  её нет совсем. В окне секретных записей: «Рассекретить», «Реабилитировать», «Сжечь дело».
- «Сжечь дело» (пока только реабилитированные) — удаляет все строки дела из того архива, где оно
  лежит. Без бэкапов, без акта.
- Защита засекреченных мест ссылки (нельзя сослать папку в Сибири повторно) сохраняется и для
  программы без прав администратора.
- Сетевые диски — «заграница»: программа с ними не работает ни в одну сторону (см. «Заграница»).

## Не цели

- Атрибут «скрытый» на ссылке или папке — отказались (риск, что программы-владельцы не найдут данные).
- CLI-команды для засекречивания, сжигания и секретного архива — агентам эти действия не нужны.
- Шифрование архива; защита от удаления секретного файла целиком (папка `%LOCALAPPDATA%\Sibir`
  принадлежит пользователю — удалить файл он может, прочитать — нет).
- Режим террора («Большой Террор», «политический террор») — отдельная задача; в нём же — сжигание
  дел в любом статусе, кроме незаконченных.

## Анти-цели

- Обычный процесс читает секретный архив или меняет в нём записи.
- Засекреченная папка теряет возможность реабилитации (из окна администратора).
- После засекречивания или сжигания в общем архиве остаются следы дела (строки, бэкап-файл).
- Сожжено дело незаконченной операции (`in_transit`, `rehabilitating`) — `recover` перестал бы работать.
- Засекреченную папку в Сибири можно сослать повторно, потому что проверки её «не видят».

## Подходы (выбран 1)

1. **Сейф на правах Windows + невидимая метка на папке.** Файл с ACL: администраторы — полный
   доступ, пользователь — только дописывать. Метка в альтернативном потоке NTFS на папке в Сибири,
   чтобы обычный процесс знал «это засекреченное место ссылки». Выбран: прячет от всех процессов без
   прав, просто, без ключей.
2. Скрытый файл с точкой без ACL — прочтёт любой процесс; не подходит под «от всех, кого возможно».
3. Шифрование с ключом, доступным только администраторам — та же защита, что у 1, но больше кода и
   способов сломаться.

## Как

### Секретный архив
- Файл `%LOCALAPPDATA%\Sibir\.secret.jsonl`, атрибут Hidden. Формат и семантика — как у
  `archive.jsonl` (`ArchiveRecord`, поздняя строка с тем же `Id` заменяет раннюю; пустые строки
  пропускаются).
- ACL (защищённый, без наследования): `BUILTIN\Administrators` — FullControl; `SYSTEM` — FullControl;
  текущий пользователь — `AppendData | Synchronize`; `OWNER RIGHTS` (S-1-3-4) — `Synchronize`
  (гасит неявные права владельца на чтение и смену ACL, т.к. файл, созданный без прав, принадлежит
  пользователю).
- Создаётся при первой записи любым процессом сразу с этим ACL. Процесс администратора при открытии
  переустанавливает ACL, если он не такой.
- Дописывание без прав: открыть только на `AppendData`, писать `\n` + строку + `\n` (прочитать конец
  файла нельзя, поэтому всегда начинаем с новой строки).

### Засекретить (главное окно, любой пользователь)
Порядок: (1) дописать дело в секретный архив; (2) поставить метку на папку в Сибири (только для
«сослан»); (3) снять печать, если её ставили мы (`StampCreated`): удалить `desktop.ini` в папке
ссылки и атрибут System со ссылки — в секретной записи `StampCreated = false`; (4) удалить все строки
дела из общего архива (переписать файл: временный файл в той же папке → замена, без бэкапа).
Сбой между (1) и (4) оставляет дело в обоих архивах — повторное «Засекретить» допустимо и
идемпотентно; при чтении в процессе администратора дубликат по `Id` показывается один раз.

### Метка засекреченного места
- Альтернативный поток `Peressylkin.secret` (пустой) на папке в Сибири (`Target`). Содержимое папки
  не меняется, в Проводнике не видно.
- `Checks`: источник, равный папке с меткой или лежащий внутри неё (проверка предков источника),
  получает отказ `in_siberia` — как для открытого дела.
- Для засекреченного дела «реабилитирован» метка не ставится.

### Реабилитация засекреченной папки
- В процессе без прав (меню Проводника, GUI, CLI): если источник — junction, дела в общем архиве нет, а
  на цели ссылки метка — ответ «Дело засекречено. Реабилитация — по санкции прокурора» (новая строка
  `Strings.Classified`). GUI предлагает перезапуск от администратора (`Elevation.Relaunch`). CLI —
  код 5, `reason: needs_admin`, без подробностей дела (агенту дело не раскрывается).
- В процессе администратора реабилитация ищет дело в обоих архивах. Прогресс засекреченного дела
  пишется в секретный архив (дело не утекает в общий). После успеха метка снимается.
- `recover` в процессе администратора проверяет и секретный архив.

### Окно «Секретные записи» (только администратор)
Таблица как в главном окне (по секретному архиву). Действия по выбранным:
- **Рассекретить** — обратный порядок: дописать в общий архив, удалить из секретного, снять метку,
  вернуть печать, если `--no-stamp` не было выбрано (по умолчанию — вернуть).
- **Реабилитировать** — как выше.
- **Сжечь дело** — см. ниже.

### Сжечь дело
- В главном окне (общий архив) и в окне секретных записей (секретный).
- Решение пользователя: сейчас — **только для «реабилитирован»**. Сжигание дел в других статусах
  (в т.ч. «сослан») — только в режиме террора (отдельная задача, см. «Не цели»), здесь не делается.
- Подтверждение одной строкой.
- Удаление — переписыванием файла без бэкапа.
- Для режима террора на будущее (не делать сейчас): сжигание «сослан» — подтверждение с последствиями
  («Папка останется в Сибири, ссылка продолжит работать, но вернуть её Перессылкин уже не сможет —
  только вручную»), снятие метки, признака в корне и нашей печати; `in_transit`/`rehabilitating` —
  никогда.

### Заграница (сетевые пути)
- Решение пользователя: сетевые диски не поддерживаются вообще, отдельного режима не будет.
- Отказ с текстом «За границу не ссылают — высылают. А высланных не реабилитируют» для любого
  сетевого пути: источник (`exile`/`check`), корень Сибири (уже есть, `network_target`), путь в
  `rehab`/`status`, а также ссылка, чья цель указывает на сетевой путь (сделана не нами).
- Код `network_target` остаётся (стабильный); для источника — новый `network_source`. Оба в `schema`.
  `Strings.NetworkTarget` заменяется новым текстом.

### Запись архивов
- Все записи в `archive.jsonl` и `.secret.jsonl` (дописывание и переписывание) — под одним
  межпроцессным именованным mutex. Без этого переписывание при «Засекретить»/«Сжечь» теряет строку,
  дописанную в это время другим процессом (меню Проводника, CLI, повышенный rehab).
- Временный файл секретного архива создаётся сразу с защищённым ACL.
- Дописывание без прав — через `CreateFile` с `FILE_APPEND_DATA | SYNCHRONIZE` (обычный
  `FileStream` просит `GENERIC_WRITE`, а `Archive.Write` читает последний байт — оба не годятся).
- `Mover` выбирает архив по записи: прогресс засекреченного дела пишется в секретный.

### Печать при засекречивании
- Новое поле записи `StampRemoved` (печать снята при засекречивании). «Рассекретить» возвращает
  печать только при `StampRemoved = true`. Пункт про `--no-stamp` выше этим заменяется: само
  `StampCreated` не отличает `--no-stamp` от чужого `desktop.ini`.
- Порядок засекречивания: сначала снять печать (`desktop.ini` + атрибут System на ссылке +
  `SHChangeNotify`), потом записать дело с `StampCreated = false, StampRemoved = true`.

### Что видит обычный процесс
- `status` засекреченной ссылки отвечает так же, как `rehab`: код 5, `needs_admin`, без подробностей.
- Незаконченное засекреченное дело обычный процесс не видит; окно администратора при запуске само
  предлагает его доследовать, `recover` от администратора проверяет оба архива.

### Права администратора (решение пользователя: не мудрить)
- Поддерживается только повышение той же учётной записи (UAC «Да»). Отказ в UAC или не введён
  пароль — ошибка, окна секретных записей нет.
- Если повышенный процесс оказался другой учётной записью (UAC с паролем чужого администратора), он
  не видит архив пользователя — показать ошибку с объяснением и не открывать секретные записи.
  Проверка: `Elevation.Relaunch` передаёт SID исходного пользователя, повышенный процесс сравнивает
  со своим.

### Вскрытый сейф (решение пользователя)
- Перед дописыванием обычный процесс пробует открыть `.secret.jsonl` на чтение (`FILE_READ_DATA`) и
  `READ_CONTROL`. Удалось — файл подменён или ACL снят: засекречивание отказывается с текстом «сейф
  вскрыт», ничего не пишет. Администратор при открытии восстанавливает ACL.

### Тома без потоков (решение пользователя)
- Если том цели не поддерживает альтернативные потоки (exFAT/FAT32 и т.п.), «Засекретить» для
  сосланного дела недоступно, с коротким объяснением. Реабилитированное засекретить можно (метка не
  нужна).

### Признак в корне Сибири (решение пользователя)
- При засекречивании сосланного дела в корень Сибири ставится незаметный признак «здесь есть
  засекреченные» (альтернативный поток `Peressylkin.secret` на корне, как метка на цели).
- `Checks`: источник, внутри которого лежит корень с этим признаком, получает отказ
  `peressylkin_property` — как сейчас для папки с открытыми сосланными делами (`Checks.cs:91`).
- Признак снимается, когда в этом корне не остаётся засекреченных сосланных дел (проверяет процесс
  администратора при рассекречивании и реабилитации).

## Решения исполнителя (отмечены как мои)

- Имя файла `.secret.jsonl`, имя потока `Peressylkin.secret`, тексты подтверждений.
- Mutex на запись архивов, поле `StampRemoved` и порядок снятия печати, код `network_source`,
  ответ `status` для засекреченной ссылки, доследование засекреченного
  дела через окно администратора.
- Проверка «повышен другой пользователь» через SID в аргументах `Relaunch`; признак в корне Сибири
  как поток на корне и правило его снятия.
- Где кнопки «Засекретить» и «Сжечь дело» в главном окне (контекстное меню строки и/или кнопки).
- Сжечь дело в общем архиве может любой пользователь (без прав администратора).
