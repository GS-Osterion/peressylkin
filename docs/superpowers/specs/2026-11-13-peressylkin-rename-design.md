# Переименование в Peressylkin («Пересылкин») — дизайн

## Зачем

`sibir` — слишком общее имя для публичного проекта. Новое имя **Peressylkin**: пересылка —
одновременно пересыльная тюрьма и отправка; «-кин» делает из неё персонажа (тов. Пересылкин,
заведует этапами). Тема и русское название «Ссылка в Сибирь» не меняются: папки по-прежнему
ссылают в «Сибирь».

## Цели

- Всё, что человек видит и набирает, называется Peressylkin: репозиторий, exe, справка CLI,
  README, AGENTS.md, skill для агентов, архив релиза.
- Скрытые имена остаются: `%LOCALAPPDATA%\Sibir` (архив дел, настройки), ключи меню
  `SibirExile/SibirRehab/SibirCase`, namespace `Sibir`, проекты `src/Sibir`, папка назначения
  `X:\Сибирь`, коды `reason` (`in_siberia` и др.). Это задокументировано как намеренное.
- Архив дел и Сибирь явно помечены как имущество Пересылкина и защищены от ссылки.

## Не цели

- Режим «Большой Террор» (идея Миши) — отдельная задача, следующая. Здесь только оставляем
  ему место: новая защита выдаёт свой код отказа, который террор позже сможет снять.
- Английская локаль — отдельный проект.
- Миграция данных: её нет, потому что скрытые пути не меняются.

## Анти-цели

- Пользователь версии 1.0.0 теряет архив дел или пункты меню после обновления.
- Агент или CLI может сослать архив дел.

## Подходы (выбран 2)

1. Только вывеска (репо, README) — внутри `Sibir.exe`, разнобой.
2. **Видимое — Peressylkin, скрытое — как было.** Нет миграции, обновление поверх.
3. Полное переименование с миграцией архива и реестра — риск для данных ради невидимой красоты.

## Как

**Репозиторий.** `GS-Osterion/sibir` → `GS-Osterion/peressylkin` (GitHub оставляет
редиректы), обновить `origin`.

**Exe.** `AssemblyName` = `Peressylkin` → `Peressylkin.exe`. Проекты и namespace не трогаем.
`ShellIntegration.InstalledExe` = `%LOCALAPPDATA%\Sibir\Peressylkin.exe`. При «Встать на учёт»
после записи меню на новый exe старый `Sibir.exe` в папке установки удаляется (если занят —
молча оставить, меню уже на новом). «Сняться с учёта» удаляет оба.

**Тексты.** README (+ ссылка-пояснение «раньше Sibir»), `dist-readme.txt`, AGENTS.md,
`docs/claude-skill/SKILL.md` (skill `peressylkin`), справка и `schema` CLI (`tool`),
`build.ps1` (`out\Peressylkin.exe`), имя архива релиза. `Strings.AppName` остаётся
«Ссылка в Сибирь» — это название для людей; заголовок окна — на усмотрение исполнителя.

**Метки.** Программа кладёт текстовый файл-табличку:
- в `%LOCALAPPDATA%\Sibir` — «Архив тов. Пересылкина»: что здесь (архив дел, без него
  реабилитация не найдёт сосланных), что имя `Sibir` — историческое, не удалять и не переносить;
- в корень каждой Сибири (`X:\Сибирь`) — «Сибирь тов. Пересылкина»: здесь живут сосланные
  папки, на них ведут ссылки, вручную не трогать.
Табличка создаётся при установке и при первой ссылке в данный корень; если её удалили —
пересоздаётся при следующей операции. Отсутствие таблички ничего не ломает.

**Защита.** Новая проверка в `Checks`, код `reason` = `peressylkin_property`, текст в духе
«Имущество тов. Пересылкина. Ссылке не подлежит». Отказ, если источник:
- совпадает с папкой архива или лежит внутри неё;
- является её предком (например, `AppData\Local`) — иначе архив уедет вместе с ним;
- содержит табличку (в самой папке, без обхода поддерева) — ловит Сибирь и архив по любому пути.
Соседи архива не затронуты: `AppData\Local\papja` ссылать можно (если не запрещено другими
проверками), а `AppData` и `AppData\Local` целиком — нельзя (утверждено пользователем).
Существующая `in_siberia` остаётся. Работает одинаково в GUI и CLI; флагов обхода нет.

**Версия** 1.1.0, после — релиз на GitHub с архивом.
