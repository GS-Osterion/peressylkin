# «Ссылка в Сибирь» — спецификация

Дата: 2026-11-11 · Статус: на утверждении

## 1. Цель

Освобождать место на системном диске, перенося папки на другой диск и оставляя
на старом месте junction, так чтобы ни Windows, ни программы, обращающиеся к
этим данным, не заметили смены места хранения. Инструмент для людей, которые не
могут или не хотят настраивать пути программ вручную. Распространение — среди
знакомых, без установщика и без прав администратора.

Успех: папка перенесена, программа-владелец работает с ней как раньше (читает и
пишет), место на исходном диске освобождено; любой перенос обратим
(«реабилитация»); сбой на любом шаге не теряет данные.

Не входит: удаление файлов (это будущий сканер кэшей — там уместен «расстрел»),
перенос без ссылки, перенастройка лаунчеров (это «дело КГБ», то есть пользователя).

## 2. Стиль

Юмор — советская бюрократия и ссылка: ссылка, этап, пересылка, прописка,
жилплощадь, дело, архив «Хранить вечно», амнистия, реабилитация, комсомольская
путёвка. Без шуток про расстрелы. Все тексты для людей — в одном файле ресурсов
строк (`Strings.cs`), чтобы их можно было править без поиска по коду.

| Ситуация | Текст |
|---|---|
| Пункт меню (папка) | Сослать в Сибирь… |
| Пункт меню (сосланная папка) | Реабилитировать · Личное дело |
| Выбор места | Куда этапировать? |
| Подтверждение | С вещами на выход! |
| Сводка | Осуждённых: N · Общий вес: X ГБ |
| Прогресс | Столыпин в пути… |
| Тот же диск | Это не ссылка, а прогулка по камере |
| Системная папка | Член Политбюро. Неприкосновенен |
| Уже сослана | Повторно не судят |
| Мало места | В Сибири мест нет: нужно X, свободно Y |
| Съёмный диск | Шаг влево, шаг вправо… Вынешь флешку — побег |
| Файл занят | Подследственный оказывает сопротивление: его держит <процесс> |
| Лаунчер | Дело передано в органы. Гражданин под надзором <лаунчер>; переселение — в компетенции КГБ (вашей) |
| Microsoft Store | Особый режим, ссылке не подлежит. Параметры → Приложения → Переместить |
| Нужны права | Требуется санкция прокурора |
| Готово | Этап прибыл. Освобождено жилплощади: X ГБ. Дело сдано в архив — хранить вечно |
| Откат | Амнистия! Все возвращены по месту прописки |
| Незакрытые дела | Доследование |
| Нет других дисков | Сибирь не найдена. Этап отменён |

Иконка программы — силуэт усов и трубки. Иконка сосланной папки — красный штамп.
Обе генерируются скриптом сборки; пользователь может подложить свою картинку
(слот `assets/custom-*.png` → перекрывает сгенерированную).

## 3. Устройство

- Один файл `Sibir.exe`, C#, WinForms, целевая платформа .NET Framework 4.8
  (есть в любой Windows 10/11 — пользователю ничего ставить не нужно). Сборка —
  .NET SDK (`dotnet build`, `TargetFramework=net48`, `LangVersion=latest`) через
  `build.ps1`; системный `csc.exe` не годится — он поддерживает только C# 5.
  Тесты — xUnit на net48 (`dotnet test`). Подсистема — Windows (GUI); консольный режим подключается к
  консоли родителя (`AttachConsole(ATTACH_PARENT_PROCESS)`) или пишет в
  перенаправленные дескрипторы.
- Режим определяется аргументами: нет аргументов → окно «Сибирь»
  (встать/сняться с учёта, архив); `--menu-exile|--menu-rehab|--menu-case <путь>` →
  окна из контекстного меню; подкоманды (§6) → консольный режим.
- Установка — «Встать на учёт»: копия в `%LOCALAPPDATA%\Sibir\Sibir.exe`, пункты
  меню в `HKCU\Software\Classes\Directory\shell\...`. Без прав администратора.
  «Реабилитировать» и «Личное дело» по возможности показываются только на
  junction (фильтр `AppliesTo` по атрибуту reparse point). Если фильтр в Windows
  11 не сработает — пункты видны на всех папках, а на обычной программа отвечает
  «Не числится в архиве» (и «Повторно не судят» при попытке сослать junction). «Сняться с учёта» убирает ключи и программу,
  архив оставляет.
- Мультивыбор: Explorer запускает процесс на каждую папку. Первый процесс
  захватывает именованный мьютекс и ~400 мс принимает пути от остальных через
  именованный канал; остальные передают путь и завершаются.
- Модули (каждый с одной задачей):
  - `Strings` — все тексты.
  - `Checks` — проверки шага 0, возвращают код причины.
  - `LauncherDetect` — распознавание лаунчеров, только чтение.
  - `Mover` — этап, досмотр, подмена, контроль, откат; не знает про UI.
  - `Junction` — создание/чтение/удаление junction (DeviceIoControl), symlink для файлов.
  - `Archive` — журнал `%LOCALAPPDATA%\Sibir\archive.jsonl`.
  - `LockFinder` — Restart Manager API, кто держит файлы.
  - `Shell` — регистрация меню, мультивыбор, штамп.
  - `Gui` / `Cli` — две оболочки над одним ядром.
  - `SelfTest` — полигон.

## 4. Место назначения

- По умолчанию: последний выбранный путь, если его диск существует и не равен
  диску-источнику; иначе `<диск>:\Сибирь\` на несъёмном диске с наибольшим
  свободным местом, кроме исходного; нет таких → отказ.
- Раскладка по умолчанию повторяет исходный путь:
  `C:\Users\rylov\AppData\Roaming\Avorion → T:\Сибирь\C\Users\rylov\AppData\Roaming\Avorion`.
  Галочка «Класть по имени» → `T:\Сибирь\Avorion` (при конфликте имени — отказ).

## 5. Процедура

Шаг 0 — проверки (ничего не меняют), каждая с кодом причины:
`already_exiled` (источник — reparse point), `protected` (Windows, корень
Program Files, корень профиля, WindowsApps, XboxGames, корни дисков),
`same_drive` (сравниваются тома, а не буквы: `subst` и точки монтирования
учитываются), `network_target` (junction не может вести на сетевой путь — отказ),
`no_space` (размер + 5% запаса), `removable_target` (только
предупреждение), `launcher` (см. ниже), `nested` (выбраны папка и её подпапка —
берётся верхняя), `target_exists` (непустая папка назначения).

Распознавание лаунчеров (`launcher`): Steam (`libraryfolders.vdf`, папка внутри
`steamapps\common`), Epic (манифесты `.item` в `ProgramData\Epic`), GOG (реестр
`GOG.com\Games`), EA, Ubisoft, Battle.net (их конфиги/реестр), Microsoft Store
(`WindowsApps`, `XboxGames` → жёсткий отказ `store_app`), программы из
`Uninstall` с `InstallLocation` → только предупреждение «при переустановке может
вернуться по месту прописки». Для лаунчеров GUI предлагает [Отпустить]
[Всё равно сослать]; CLI — `--ignore-launcher`.

Шаг 1 — сопротивление: переименовать источник и сразу вернуть. Ошибка → через
Restart Manager найти процессы → `locked` с их именами. GUI: [Повторить] [Пропустить].

Запись в архив со статусом `in_transit` делается до шага 2.

Шаг 2 — этап: копирование в `<цель>.~пересылка`. `CopyFileEx`; для файлов
> 256 МБ — `COPY_FILE_NO_BUFFERING`; мелкие файлы — параллельно (4 потока).
Сохраняются атрибуты и даты файлов и папок. Вложенные junction/symlink
воссоздаются как ссылки, а не копируются по содержимому. Пути > 260 символов —
через префикс `\\?\`. ACL не копируются: копия наследует права папки назначения.

Шаг 3 — досмотр: совпадают дерево, число файлов и размеры. `--strict` / галочка
«Строгий досмотр» — дополнительно SHA-256 каждого файла.

Шаг 4 — подмена: источник → `<имя>.~этап` (переименование на том же диске);
`~пересылка` → окончательное имя; junction на старом месте; штамп.

Шаг 5 — контроль: перечислить дерево через junction и сверить с досмотром.

Шаг 6 — удалить `<имя>.~этап`; статус в архиве → `exiled`.

Откат («амнистия») при ошибке на любом шаге: удалить junction, если создан;
вернуть `~этап` на место; удалить `~пересылка`; статус `amnestied`. Оригинал
не изменяется до успешного шага 3.

Доследование: при каждом запуске (и командой `recover`) ищутся записи
`in_transit`. По наличию `~этап`/`~пересылка`/junction решается: если junction и
полная копия на месте — завершить (шаги 5–6); иначе — откат.

Несколько папок обрабатываются последовательно и независимо; в конце сводка.

Штамп: в папку назначения пишется скрытый системный `desktop.ini` с
`IconResource=%LOCALAPPDATA%\Sibir\stamp.ico,0` (иконка кладётся рядом с
программой при «Встать на учёт»); на junction ставится атрибут System.
Галочка «Ставить штамп» (по умолчанию вкл.). При реабилитации `desktop.ini`
удаляется, если его создала программа (метка в архиве).

Права администратора нужны для ссылок на отдельные файлы (symlink) и для
защищённых мест (`ProgramData` и т. п., определяется пробной записью). GUI
перезапускает себя с `runas` («Требуется санкция прокурора»); CLI не повышает
права, а возвращает код 5 и готовую команду.

Реабилитация: проверка места на исходном диске → копия обратно в
`<имя>.~возвращение` → досмотр → удалить junction → переименовать в исходное имя
→ удалить `desktop.ini` штампа → удалить копию в Сибири → статус
`rehabilitated`. Тот же откат и доследование.

## 6. Консольный режим (для ИИ и скриптов)

```
Sibir.exe check   <путь>... [--to <папка>]
Sibir.exe exile   <путь>... [--to <папка>] [--yes] [--strict] [--ignore-launcher] [--by-name] [--no-stamp]
Sibir.exe rehab   <путь>... [--yes]
Sibir.exe status  <путь>
Sibir.exe list
Sibir.exe recover [--yes]
Sibir.exe schema
```

- Без `--yes` изменяющие команды выполняют только проверку (как `check`).
- `--json`: stdout — по одному JSON-объекту на путь:
  `{"path","verdict","reason","message","target","bytes","processes"}`;
  `reason` — стабильный английский код, `message` — текст для людей.
  Прогресс — JSON-строки в stderr.
- Никаких интерактивных вопросов и окон.
- Коды выхода: 0 успех · 2 отказ проверок · 3 занято процессом · 4 сбой с откатом
  · 5 нужны права администратора · 6 есть незакрытые дела · 1 ошибка аргументов.
- `schema` выводит описание команд, флагов, кодов и формата JSON.
- `AGENTS.md` в корне репозитория — шпаргалка для агентов; безопасный порядок:
  `check` → `exile --yes`. Опционально — skill для Claude Code.

## 7. Проверка

- `Sibir.exe selftest [--to <папка на другом диске>]` — полигон через консольный
  режим: мелкие тысячи и большой файл, пустые папки, read-only/hidden, кириллица
  и пробелы, пути > 260, вложенный junction; ссылка → чтение/запись через
  junction → реабилитация → побайтная сверка; занятый файл → отказ без изменений;
  обрыв на шаге 4 → доследование восстанавливает; запреты шага 0. Итог одной
  строкой.
- Проверить, что PowerShell и Git Bash дожидаются завершения и получают код выхода.
- Боевое крещение: Avorion (`%APPDATA%\Avorion`, 0,92 ГБ, 1881 файл — корабль
  пользователя, ценность высшая). До испытания — полная копия папки на E: со
  сверкой числа файлов и размеров; без неё испытание не начинается. Ссылка →
  игра загружает сейв, играем, сохраняемся → новые файлы на T: → реабилитация →
  игра работает. Затем Zomboid (`C:\Users\rylov\Zomboid`) и Barotrauma
  (`%LOCALAPPDATA%\Daedalic Entertainment GmbH`) одним мультивыбором — тоже с
  предварительной копией на E:.
